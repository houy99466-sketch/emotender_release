# EmoTend NRC 情绪评估与空间氛围方案设计

## 1. 目标与范围

本次改造包含两个相互衔接的功能：

1. 将当前由 LLM 自由生成的六类情绪判断，升级为以 NRC 八类基本情绪为统一标签空间、以 VAD 为连续维度校验、以当前会话证据为依据的标准化情绪评估。
2. 在正式饮品推荐的确认页面提供一个可选的“空间氛围方案”，针对空调、灯光和空气净化器生成设置建议，但不连接或控制真实设备。

本次不接入米家账号、设备授权、设备发现、设备状态读取或控制接口；不迁移 MiMo；不替换现有酒类菜单；不修改六维风味名称。

## 2. 设计原则

- NRC 八类情绪是统一类别，不把词典命中次数直接当作心理学概率。
- LLM 负责理解上下文、否定、转折和反讽，固定规则负责校验结构和范围。
- 当前情绪只依据用户本轮原话与当前会话，不读取长期 profile 中的历史情绪。
- 用户明确自述优先于模型根据措辞进行的推断。
- 每一个有效情绪都必须绑定当前会话中的原话证据。
- 八类情绪先生成目标风味向量，再由饮品库确定实际方案；不能直接篡改真实饮品属性。
- 空间氛围设置属于体验建议，不宣称具有医疗、心理治疗或健康改善作用。
- 新结构保留现有 `emotion_label` 和 `emotion_blend`，避免破坏当前 Web UI、APK 和历史测试。

## 3. 五种情绪机制的职责

### 3.1 Russell 情感环形模型

使用愉悦度 `valence` 和唤醒度 `arousal` 描述情绪位置。它用于判断情绪的大方向，不直接生成最终类别。

### 3.2 PAD/VAD

在愉悦度和唤醒度之外增加控制感 `dominance`。它用于区分方向相近但控制感不同的状态，例如愤怒与恐惧。

### 3.3 Geneva Emotion Wheel

本版本不直接实现 Geneva Emotion Wheel。它只作为未来用户自选情绪或情绪强度界面的设计参考，不进入当前推理链路。

### 3.4 NRC Emotion Lexicon

统一标签空间为：

- `anger`：愤怒
- `anticipation`：期待
- `disgust`：厌恶
- `fear`：恐惧
- `joy`：喜悦
- `sadness`：悲伤
- `surprise`：惊讶
- `trust`：信任

NRC 负责规定“可以输出哪些情绪”，LLM 负责根据中文上下文对八类情绪评分。后续取得并确认适用许可的中文 NRC 词典后，可以把词典命中结果作为辅助证据，但不能替代上下文分析。

### 3.5 SAM 自评

本版本不要求用户每轮填写量表。在情绪报告中提供“分析不准确”的修正入口时，可让用户轻量调整情绪类别；该能力不进入本次首轮实现。

## 4. 情绪评估数据结构

在现有 `control_json` 中新增 `emotion_assessment`：

```json
{
  "emotion_assessment": {
    "taxonomy": "nrc_emolex_8",
    "scores": {
      "anger": 0.00,
      "anticipation": 0.10,
      "disgust": 0.00,
      "fear": 0.55,
      "joy": 0.00,
      "sadness": 0.25,
      "surprise": 0.00,
      "trust": 0.10
    },
    "valence": -0.55,
    "arousal": 0.72,
    "dominance": 0.28,
    "primary_emotion": "fear",
    "confidence": 0.82,
    "evidence": [
      {
        "quote": "明天就要答辩了，我脑子停不下来",
        "emotions": ["fear", "anticipation"],
        "interpretation": "对即将发生的事件担忧，负向、高唤醒、控制感偏低"
      }
    ],
    "clarification_needed": false
  }
}
```

约束如下：

- `scores` 必须包含全部八个固定键。
- 每项分数范围为 `0.0` 至 `1.0`，总和允许误差不超过 `0.05`。
- `valence` 范围为 `-1.0` 至 `1.0`。
- `arousal`、`dominance` 和 `confidence` 范围为 `0.0` 至 `1.0`。
- `primary_emotion` 必须是八个固定英文键之一，并对应最高分；并列时由当前原话证据更直接的一项优先。
- `evidence.quote` 必须能在本轮用户原话或当前会话历史中找到，不允许引用长期 profile。
- 证据不足时 `confidence` 必须降低，`clarification_needed` 设为 `true`。

## 5. 与现有字段兼容

现有字段继续返回：

- `emotion_label`：由 `primary_emotion` 映射成当前表情系统支持的中文状态。
- `emotion_blend`：从 `scores` 中选取分数大于零的前三项，转成现有 `{emotion, weight, source}` 结构，并重新归一化。
- `complex_emotion`：由八类构成、VAD 和当前证据生成简短自然语言描述。
- `face_state`：根据主情绪、VAD 和现有允许值生成。

现有六类状态不再承担底层情绪标准，只作为当前表情、旧饮品菜单和兼容层使用。兼容映射必须放在独立常量中，不散落到 Prompt 和前端条件判断里。

## 6. 推理与校验流程

```text
本轮文字与当前会话
→ 提取明确自述、事件、否定、转折和时间指向
→ LLM 输出 NRC 八类分数、VAD、置信度和证据
→ 后端执行键名、类型、范围、总和和证据原文校验
→ 使用 VAD 检查情绪方向是否明显矛盾
→ 生成兼容字段 emotion_label、emotion_blend 和 face_state
→ Mode Router 决定继续聊天、澄清或进入正式推荐
```

VAD 校验不重新推测用户情绪，只检查结果是否自洽。出现结构错误、分数总和错误、证据无法在当前会话中找到或 VAD 明显冲突时，后端要求 LLM 重试；重试仍失败则使用中性兼容结果，并保留错误信息供日志检查。

当前 `emotion_history` 可以继续用于调整回复语气，但不能作为本轮 NRC 分数的证据，也不能覆盖用户本轮明确自述。

## 7. 八类情绪到六维风味

六维风味保持：甜度、茶感、奶香、果香、清爽度、口感层次。

系统维护一个固定的 `8 × 6` 情绪风味映射矩阵。NRC 八类分数与该矩阵加权计算，得到“目标风味向量”。目标向量只参与饮品检索和推荐排序：

```text
NRC 八类分数
→ 固定映射矩阵加权
→ 目标六维风味
→ 叠加用户稳定口味和饮食限制
→ 在合法饮品配置中检索最接近方案
→ 使用实际饮品配置生成最终六维图
```

因此，情绪不会直接决定最终饮品参数。正式报告展示的是实际饮品的六维结果，不是情绪映射产生的目标向量。

本次先建立矩阵的数据结构和计算边界；矩阵数值应通过团队评审和测试语料调整，不写入 Prompt。

## 8. 空间氛围方案

### 8.1 页面位置

在正式推荐预览页的“饮品构成示意”下方、`确认方案`按钮上方增加一个关闭状态的开关：

```text
同步生成空间氛围方案  [开关]
仅生成建议，不会实际控制设备
```

关闭时现有流程完全不变。打开后，用户确认饮品方案时同步生成空间氛围方案，并在最终报告中显示。

### 8.2 三类设备

- 空调：建议目标温度。
- 灯光：建议亮度与色温。
- 空气净化器：建议运行模式，固定为自动、静音或增强三种之一。

所有值由固定规则根据 `emotion_assessment` 生成，不允许 LLM 自由输出任意设备名称、单位或模式。

### 8.3 数据结构

在 `control_json` 的正式推荐结果中增加可选字段 `ambient_plan`：

```json
{
  "ambient_plan": {
    "enabled": true,
    "disclaimer": "方案预览，不会实际控制设备",
    "air_conditioner": {
      "temperature_c": 25,
      "reason": "降低高唤醒状态下的闷热感"
    },
    "light": {
      "brightness_percent": 45,
      "color_temperature_k": 3200,
      "reason": "使用较柔和的暖色照明降低视觉刺激"
    },
    "air_purifier": {
      "mode": "silent",
      "reason": "保持低噪声的稳定空间"
    }
  }
}
```

当用户未开启选项时，`ambient_plan.enabled` 为 `false`，其他三个设备字段不返回。前端不把该选择写入长期 profile。

### 8.4 生成规则

空间方案以 `arousal` 为主要输入，以 `valence` 和 `dominance` 为辅助输入，再结合 NRC 主次情绪选择固定预设。参数必须限制在产品定义的演示范围内：

- 空调温度：`22` 至 `28` 摄氏度的整数。
- 灯光亮度：`20` 至 `100` 的整数百分比。
- 灯光色温：`2700` 至 `6500` 开尔文的整数。
- 空气净化器模式：`auto`、`silent`、`boost`。

第一版报告中的参数允许展示，不提供编辑和发送设备指令的操作。

## 9. 前后端职责

### 后端

- 在 Prompt 中加入 NRC 八类定义、评分顺序、证据要求和 VAD 规则。
- 校验 `emotion_assessment` 的完整性和自洽性。
- 生成现有兼容情绪字段。
- 计算目标六维风味向量，但保持实际饮品六维值的来源不变。
- 根据用户开关生成确定性的 `ambient_plan`。

### 前端

- 情绪饼图改为展示 NRC 八类中本轮非零的情绪构成。
- 保持现有动态表情和正式推荐流程。
- 在确认页增加空间方案开关。
- 在最终报告中按开关状态显示或隐藏空间氛围方案。
- 保存长图时包含已显示的空间氛围方案。

## 10. 错误处理

- NRC 分数缺键、类型错误或总和不合法：拒绝结果并重试 LLM。
- 证据不在当前会话中：拒绝结果并重试 LLM。
- `primary_emotion` 与最高分不一致：拒绝结果并重试 LLM。
- VAD 与主情绪明显冲突：降低置信度并重试一次。
- 空间参数越界或模式非法：后端使用对应预设的安全默认值并记录日志。
- 空间方案生成失败：饮品推荐仍然可确认，最终报告隐藏空间方案并提示本轮未生成。

## 11. 测试与验收

### 情绪评估

- 覆盖八种 NRC 情绪的明确表达。
- 覆盖正向高唤醒、正向低唤醒、负向高唤醒和负向低唤醒。
- 覆盖混合情绪、否定、转折、反讽、证据不足和无关输入。
- 覆盖当前状态与长期 profile 历史情绪冲突的场景。
- 验证每个证据引文都来自当前会话。
- 验证八项分数总和、VAD 范围、主情绪和置信度。

### 风味和空间方案

- 同一情绪输入产生确定的目标风味向量和空间预设。
- 关闭开关时不显示空间方案，且原推荐流程不受影响。
- 打开开关时最终报告显示三个设备的完整建议。
- 所有设备参数处于规定范围，空气净化器模式只能使用三个固定值。
- 保存长图包含空间方案，且移动端与桌面端无文字溢出或重叠。

## 12. 实施边界

本设计只定义首版标准化情绪评估和空间方案预览。真实 NRC 中文词典接入、用户情绪修正界面、真实米家设备接入、设备状态读取、参数编辑、自动化执行和 MiMo 迁移均不属于本次实现。
